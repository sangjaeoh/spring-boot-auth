# Load Report

## 언제

- SLO 목표([observability-slo](observability-slo.md))를 보정하거나 용량을 산정할 때.
- 핫패스 성능 회귀가 의심될 때(하네스 재실행으로 상대 비교).

## 하네스

- `LoadProfileIT`(app-api 테스트, 옵트인)가 실 PostgreSQL·Redis(Testcontainers) 위에서 핫패스 4개를 프로파일한다. 기본 빌드는 스킵한다.
  - 실행: `./gradlew :module-apps:app-api:test --tests LoadProfileIT -DloadProfile=true`
  - 로그인 레이트리밋만 테스트 스코프로 상향한다(엔진 용량 측정 목적). prod 실효 처리량은 레이트리밋(IP 30/분·계정 15/분)이 지배한다.
- 절대값은 하드웨어 종속이다 — 예산 검증·릴리스 간 상대 비교용으로 쓴다. prod 유사 환경 재실측은 배포 환경 확보 후 항목이다([prod-gate](prod-gate.md)).

| 로그인(Argon2) | 200 | 8 | 0 | 109.7 | 172.6 | 202.0 | 216.4 | 69 |
| 보호 API(세션 검증) | 5000 | 64 | 0 | 13.2 | 23.7 | 45.2 | 58.8 | 4377 |

| 동일 계정 로그인 경합(과부하 프로브) | 100 | 16 | 12 | 30419.6 | 30675.2 | 60561.7 | 60615.5 | 1 |

- SLO 예산 대비: 로그인 p99 202ms ≤ 1s, 보호 API p99 45ms ≤ 100ms, 리프레시 p99 128ms ≤ 300ms — 전부 예산 내.
- 동일 계정 경합 발견: 같은 계정 동시 로그인 16은 계정 행 쓰기 직렬화로 convoy가 생겨 대기가 Hikari `connectionTimeout`(기본 30s)까지 쌓인다(오류 12건 = 풀 대기 초과).
  - prod 노출은 계정 레이트리밋 15/분이 상한이라 정상 사용에서 도달 불가하고, 도달해도 해당 계정만 느려진다(타 계정 무영향 — 정상 시나리오와 병행 실측으로 확인).
  - 후속 검토: 계정 행 잠금 구간 축소(마지막 로그인 갱신 비동기화 등). 현 슬라이스에서는 위험 수용.

## 용량 산정

- Argon2 메모리 예산: peak ≈ `auth.password.hashing.max-concurrent`(auto=코어수) × 19MB. 10코어 기준 ≈ 190MB — 컨테이너 메모리는 힙 + 190MB 여유로 산정한다. 초과 요청은 500ms 대기 후 503(백프레셔)이다.
- Redis 메모리 모델: 세션당 ~4.1KB 실측(계정당 세션 ≤3). 동시 세션 100만 ≈ 4.1GB + 레이트리밋·챌린지 키(TTL 단기) 오버헤드.
- 수평 확장: 앱 무상태라 인스턴스 추가로 로그인 처리량이 선형 증가한다(제약은 Redis·DB — 세션 검증 4.4k req/s/인스턴스는 Redis 단일 노드로 수용).
